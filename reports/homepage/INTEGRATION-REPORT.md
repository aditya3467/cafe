# Cup2Eat homepage integration

The validated hero is now part of `index.html`, followed by **The Edible Coffee Experience**. The standalone prototype remains intact and independently accessible at `/prototype/hero-preview.html`. This is a local project integration; no hosting/deployment changes were made.

## Inspection and reuse

Inspected the main HTML, both CSS files, all foundation JavaScript, project inventory, prototype markup/CSS/JavaScript/cache, and prepared asset inventory/dimensions/validation data. All 239 cleaned 1280 × 720 frames and registered cup/plate/composite assets are present. No independent JPEG/WebP product photographs are present in the working tree. Historical missing tracked photos were not restored or substituted.

| Prototype component | Main implementation |
| --- | --- |
| Centre-to-destination geometry and uniform scale | Preserved in `js/hero-animation.js` |
| 0–34% movement, registered handoff, 48–94% pour, 94–100% hold | Preserved |
| GSAP driver, 0.18s scrub, pin duration | Preserved |
| Independent plate, cup and canvas, scene masks | Preserved in main HTML/CSS |
| Desktop right product area / mobile stacked geometry | Preserved |
| 18-entry ImageBitmap cache, three concurrent loads, direction-aware queue | Algorithm reused in `js/frame-cache.js` |
| Clean sequence | Referenced in place; paths now generated by `js/frame-sequence.js` relative to its module URL |
| GSAP and ScrollTrigger 3.13.0 | Existing `prototype/vendor/` files loaded exactly once each; no dependency copies |
| Temporary debug/end marker | Replaced with normal navigation, final CTA and next section |

The main animation module adds a scoped `mountHero` entry point and exposes `window.cup2eatHero` for validation. It retains the prototype's movement and rendering logic. No prototype scripts/styles are loaded as application logic; only the existing vendor distributions are shared. The main cache differs from the prototype by importing its frame URL helper rather than embedding a page-relative asset path.

## Homepage changes

- Original Cup2Eat wordmark and one navigation destination, **The experience**. No invented navigation categories.
- Existing hero headline and factual supporting text; debug UI removed.
- Final **Discover the edible experience** anchor appears during the filled-cup hold, and reverses its visibility on upward scrolling. It is inert and removed from keyboard focus before reveal.
- Experience section introduces edible waffle construction, golden diamond texture, chocolate-coated rim, and coffee with an edible cup. Existing registered cup imagery is used because separate product photographs are unavailable. No unrelated stock images, prices, testimonials, provenance or unsupported product claims.
- Semantic headings and image descriptions, a keyboard skip link, visible focus styles, focus transfer at section anchors, and explicit return-to-top handling for the pinned hero.
- Reduced motion shows readable copy/CTA and a static cup in the final desktop/mobile composition, without pinning or frame-sequence fetches. A readable static fallback remains without JavaScript.

## Regressions and remaining limits

No regression was found in the tested hero geometry, source registration, frame mapping, reverse scrolling or cache limit compared with the standalone prototype. Intentional differences are navigation, final CTA, next section, removal of debug UI, and the more useful reduced-motion static composition (visible copy plus product, with no sequence downloads).

Inherited visual limits remain: the 400px-wide cutout softens when enlarged; the reconstructed plate and full-frame scene have different gradients/tabletop/horizon details; a soft scene mask mitigates the mismatch without making it pixel-identical; the sequence brings its original shadow into the handoff; and the final filled cup is cropped by the footage. PNG transfer cost remains substantial. No new image conversion, matting, invented photography or missing lower-cup reconstruction was performed. Browser simulations are not physical-phone, Safari or screen-reader certification.

Checksums confirm **all 26 prototype files and all 494 original/prepared asset files are unchanged**. No image sequence was duplicated. Existing unrelated tracked deletions remain untouched.

## Reproduction

Run `python3 -m http.server 8000 --bind 127.0.0.1` from the project root. Open `/` for the homepage or `/prototype/hero-preview.html` for the reference. Browser checks are in `tests/homepage-browser.mjs` and `tests/homepage-accessibility.mjs`; they require Node with built-in WebSocket support and an otherwise unused Chrome page exposed on local debugging port 9222. Run sequentially while the HTTP server is active. They write only homepage reports/screenshots. The accessibility script temporarily emulates reduced motion and disables page JavaScript for the fallback screenshot, then restores script execution.
